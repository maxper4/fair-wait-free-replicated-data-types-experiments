# Wait-free Replicated Data Types Experiments
This repository contains a Rust implementation of an universal framework for Wait-free Replicated Data Types (e.g., CRDTs), and some experiments to assess their reordering and fairness under network partitions.

## Framework
### Architecture
The framework is based on a Directed Acyclic Graph (DAG) (src/dag.rs) representing the causal order of commands.
Each node in the DAG is label with an operation.
A process (src/process.rs) use this DAG to append new commands and read the current state of the replicated object (src/crdt.rs).
The current state is computed by applying a reconciliation function (different functions in src/reconciliation.rs) to the commands in the DAG.
The reconciliation functions can be modified to mutate the state only if the commands are legal e.g., not removing an element that is not present in a set (src/legal_functions.rs).
We used tokio for asynchronous local tasks (e.g., issuing commands and listening for incoming commands at the same time in src/process.rs) and for networking (src/networking.rs) between multiple processes.
The main entry point is in src/lib.rs.
If needed, DAGs can be depicted with utility function print_graph (src/rendering.rs).

### Reconciliation functions
The reconciliation functions of interest are (src/reconciliation.rs): 
- stable_reconciliation!: macro generating a function sorting commands by causality (Breadth First Search) and sorting commands at the same distance from the root by the order $order_concurrent provided as parameter of the macro. Using this macro with process id order is called fbfs in the experiments. 
- fair_reconciliation_no_n: use a round-robin of processes to execute concurrent commands in a fair way. Called ffair in the experiments.

## Branches
- networking: network features (remote)
- docker-experiments: run multi-processes experiments in docker (local but use networking)
- threads-experiments: run experiments with multiple threads simulating processes (local)

## Install

1. Make sure you have docker installed and setup correctly. To test it, type:

```text
docker version
```

Otherwise, please follow the [official documentation to install it](https://docs.docker.com/engine/install/ubuntu/).

2. You may want to use docker without sudo. To do so, type:

```text
sudo groupadd docker
sudo usermod -aG docker $USER
sudo service docker restart
```

To try it type:

```text
docker ps
```

If it's not working, you can try with :

```text
sudo chmod 666 /var/run/docker.sock
```

4. Make sure you have docker-compose installed. To test it, type:

```text
docker-compose version
```

Otherwise, you can install it with:

```text
sudo apt update
sudo apt install docker-compose
```

5. Relies on graphviz for rendering DAGs: ```sudo apt install graphviz```.
You may need to create a ``display`` directory to contain graphs.

6. Install Rust by following the instructions on the [official website](https://www.rust-lang.org/tools/install).

7. Make is used to run the experiments: ```sudo apt install build-essential make```

8. Experiments data is plotted using gnuplot: ```sudo apt install gnuplot```

## Experiments

### Single Execution
You can run a single experiment with multiple processes using docker and docker-compose.
An ``experiment`` directory is created, where a docker-compose file is generated by the script ``docker_architecture/experiment-setup.sh``, and where each process has its own subdirectory containing its logs and configuration file. 
A makefile is provided to automate most steps, including calling the experiment-setup script. 
All you need to do is:
1. Rebuild the docker image if the code was edited: ```make build```

2. Run the experiment with its parameters:```make run p=4 t=1 f=1 partition=0 d=30```

/!\ needs to run with root to use NET_ADMIN capability for networking (e.g., partitions, network delays) /!\

Parameters: 
- p: number of processes (default 4)
- t: data type (1: for reading the state as a sequence of abstract commands, 2: set with add / remove commands that fail if the added element is already present or if the removed element is already absent; default 1)
- f: reconciliation function (1: stable_reconciliation with process id order for concurrent commands (fbfs), 2: fair reconciliation (ffair); default 1)
- partition: ratio of execution in which a network partition occurs (0: no partition, 0.5: half of the execution, 1: always partitioned; default 0)
- d: duration of the experiment in seconds (default 30)


3. Stop the experiment: ```make stop``` (deletes the containers and experiment directory)

### Multiple Executions
We provide shell scripts using the makefile to run multiple experiments with varying parameters, compute the relevant metrics from the logs and plot the results.
Each scenario can be run with: ``bash script.sh``, where script.sh is:
- stability_vs_processes.sh: executes the framework for each reconciliation function fbfs and ffair with no partition and varying the number of processes in {4, 8, 12, 16}. Gathers the average number of time each command was reordered.

- fairness_vs_partition.sh: executes the framework for each reconciliation function fbfs and ffair with 16 processes and varying the partition ratio in {0, 0.1, 0.25, 0.5}. Gathers the total number of commands that stabilized in their initial context.

- fairness_vs_processes.sh: executes the framework for each reconciliation function fbfs and ffair with the partition ratio fixed to 0.33 and varying the number of processes in {4, 8, 12, 16}. Gathers the fairness ratio.

- computation_vs_commands.sh: executes the framework for each reconciliation function fbfs and ffair with 10 processes and gathers the time elapsed during the computation of each reconciliation function on DAG of size 10, 100, 500 and 1000.

For each script script.sh, the data gathered is stored in script.dat and plotted using the gnuplot script script.gp, resulting in script.tex. If you don't want to render the plots in latex, you can modify the gnuplot scripts to output in other formats (e.g., by replacing the first line by ``set terminal png size 2000,800 font ',15'``).
The data we gathered for our experiments is available in script_nosem.dat files for experiment without any semantic and in script_removewins.dat for experiments with the set data type.
